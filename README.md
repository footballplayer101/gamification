# APR, 나혼자만 레벨업

GitHub → Vercel 배포용 Next.js 웹앱입니다. 학습자는 Udemy 이메일만 입력하고, 담당자는 별도 이메일/비밀번호로 로그인합니다. ChatGPT 로그인은 사용하지 않습니다.

## 구현 범위

- 학습자: 이메일 조회, EXP 진행률, 레벨별 리워드, 익명 전체 랭킹, 추천 강의 링크
- 관리자 `/admin`: 로그인, CSV/XLSX 검증 → 미리보기 → 전체 교체 업로드, 이메일을 포함한 전체 랭킹, 추천 강의 URL 저장
- DB: 서버 전용 PostgreSQL. Vercel Marketplace의 Neon 등 PostgreSQL 제공자를 연결합니다.
- 원본 보고서와 개인 이메일은 GitHub·프런트엔드 번들에 포함되지 않습니다. 업로드는 관리자 인증 후 서버에서 처리합니다. 일반 랭킹 API는 이메일을 반환하지 않습니다.

## 이벤트 규칙

기간: 2026-10-06~2026-10-28. 모든 강의 대상.

| 누적 학습시간 | 화면 레벨 | 추첨 |
| --- | --- | --- |
| 0~15분 미만 | Lv.0 | 대상 아님 |
| 15~60분 미만 | Lv.1 | 투썸플레이스 아메리카노 쿠폰 / 10명 |
| 60~120분 미만 | Lv.2 | 배달의민족 3만원 기프티콘 / 4명 |
| 120분 이상 | Lv.3 | 메디큐브 부스터 글로우 / 2명 |

학습시간 내림차순, 동점 공동 순위(1,1,3). 소수점 학습시간으로 순위와 레벨을 계산합니다. 최종 레벨 구간에서만 추첨하며 하위 구간 재추첨과 마스크팩 지급은 없습니다. 실제 추첨 자동 실행 기능은 포함하지 않았습니다.

## 로컬 미리보기

Node.js 22.13 이상 권장.

```sh
corepack pnpm install --frozen-lockfile
cp .env.example .env.local
# .env.local에서 DEMO_MODE=true
corepack pnpm dev
```

샘플 이메일: `learner@apr-demo.example`. 이메일 입력창에서 조회합니다. 가상 데이터는 화면에 명시되며 운영 저장소로 옮겨지지 않습니다. 데모 모드에서는 실제 업로드/설정 저장이 차단됩니다.

### 첨부 보고서로 로컬 조회 테스트

이 PC에서는 비공개 `.env.local`의 `LOCAL_REPORT_MODE=true`, `LOCAL_REPORT_PATH`로 지정한 원본 CSV를 서버에서 읽어 실제 이메일 조회를 테스트할 수 있습니다. `SESSION_SECRET`도 필요합니다. 화면에 보고서 기간과 테스트 표시가 나타나며 10월 운영 실적과 분리됩니다. 원본 파일·경로·개인 이메일·로컬 환경변수는 GitHub나 소스 ZIP에 포함하지 않습니다. Vercel에서는 이 모드가 비활성화됩니다.

## GitHub 및 Vercel 배포

1. Vercel에서 **Add New → Project → footballplayer101/gamification**을 가져옵니다.
2. Framework: **Next.js**, Root Directory: 저장소 루트. `pnpm-lock.yaml`을 통해 의존성을 설치합니다.
3. 디자인 검토용 최초 배포는 환경변수 `DEMO_MODE=true`를 추가합니다. 이 경우 DB 없이 가상 학습자 화면을 확인할 수 있습니다.
4. 실제 운영은 Vercel **Storage / Marketplace**에서 PostgreSQL(예: Neon)을 프로젝트에 연결합니다. 해당 요금제를 사용자가 선택합니다.
5. PostgreSQL 콘솔에서 `db/schema.sql`을 실행합니다. 또는 로컬 `.env.local`에 DATABASE_URL을 넣고 `pnpm db:setup`을 실행합니다.
6. 로컬 터미널에서 `pnpm admin:password`를 실행하고 12자 이상의 비밀번호를 설정합니다. 출력된 해시와 세션 키만 아래 Vercel 환경변수에 저장합니다. 원문 비밀번호를 저장소에 넣지 않습니다.
7. 아래 값을 Vercel의 **Production 환경변수**에 설정한 후 다시 배포합니다.

| 이름 | 값 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 연결 문자열(서버 전용) |
| `ADMIN_EMAIL` | 사용자가 지정한 관리자 이메일 |
| `ADMIN_PASSWORD_HASH` | 비밀번호 설정 도구의 출력 해시 |
| `SESSION_SECRET` | 설정 도구의 출력 키(최소 32자) |
| `DEMO_MODE` | `false` |
| `APP_ORIGIN` | 선택 사항. 실제 배포 주소의 origin(예: https://example.vercel.app), 끝에 / 없이 |

관리자 이메일은 코드에 하드코딩하지 않습니다. 일반 이메일/비밀번호로 로그인하며 메일 발송이나 이메일 인증 링크는 사용하지 않습니다. 비밀번호 변경은 해시 교체와 SESSION_SECRET 교체 후 재배포로 처리합니다.

## 매일 운영

1. Udemy 사용자 강의 활동 보고서에서 **시작일은 반드시 2026-10-06**으로 고정하고 집계 종료일을 선택합니다. 모든 사용자·강의를 포함한 누적 CSV를 내려받습니다.
2. `/admin` 로그인 → 파일 업로드 → 같은 집계 종료일 지정 → 누적 보고서 확인 체크.
3. ‘파일 검증하기’ → 학습자 수·합계·중복 행 확인 → ‘전체 반영’.
4. 학습자 화면에서 기준일과 본인 조회 결과를 확인합니다.

매번 전체 교체하므로 동일 보고서를 재업로드해도 시간이 더해지지 않습니다. 이메일을 소문자로 정규화하고 모든 강의 시간을 합산합니다. 같은 사용자·강의의 완전히 동일한 행은 1번만 집계하며, 시간이 다른 중복 행은 오류 처리합니다. 빈 값/음수/잘못된 이메일/필수 열 누락도 반영을 차단합니다. 동시 업데이트 충돌은 revision 검사로 차단합니다.

샘플 9월 보고서는 개발 시 로컬 형식 검증에만 사용했습니다. 운영 업로드는 10/6 이후 기간의 파일만 허용합니다. CSV 원본 또는 첫 시트가 보고서인 XLSX, 최대 3MB / 100,000행 / 10,000명입니다. CSV는 UTF-8로 저장합니다.

보고서의 ‘마지막 활성 날짜’로 기간을 재필터링하지 않습니다. Udemy의 **사용한 동영상 시간(Minutes Video Consumed)**은 선택한 기간의 동영상 시간이고 마지막 활성 날짜는 그 기간 밖일 수 있습니다. 보고서 자체에 일별 시간 분해가 없으므로 관리자가 올바른 기간으로 추출해야 합니다. 파일명에 기간이 있으면 입력한 기간과 대조합니다.

집계 단위는 Udemy 보고서 수치이며 실제 접속시간·비동영상 활동 시간과 다를 수 있습니다. 반복 시청 및 배속의 반영 방식도 Udemy 집계 정의를 따릅니다. [Udemy 공식 필드 설명](https://business-support.udemy.com/hc/en-us/articles/33787385064727-Data-export-report-field-descriptions)

## 개인정보와 접근

- 학습자 조회는 본인 인증이 아닙니다. 이메일을 아는 사람은 해당 이메일의 레벨·시간·순위를 조회할 수 있습니다(합의된 방식).
- 공개 랭킹은 서버 키로 생성한 별칭만 표시합니다. 실명·이메일 목록·강의 내역은 공개하지 않습니다.
- 관리자 API는 모두 서버에서 권한을 검사합니다. HttpOnly/SameSite 쿠키, 8시간 만료, Origin 검사, DB 기반 로그인/조회 요청 제한을 사용합니다.
- 운영 로그인은 Vercel이 전달하는 클라이언트 IP를 기준으로 분당 5회, 조회는 30회 제한합니다. 동일 사내 네트워크에서는 요청 제한을 공유할 수 있습니다.
- DB 연결과 관리자 비밀번호 설정이 없으면 관리자 기능은 잠금 상태입니다.
- 권장: Production/Preview DB 분리. 실제 보고서 업로드는 Production에서만 수행합니다.
